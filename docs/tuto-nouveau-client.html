Créer un site internet pour un nouveau client

Le process complet de la réception du brief à la livraison. Le gros du travail est fait par Claude à partir d'un prompt structuré. Toi tu valides, déploies et factures.

⏱️ Ton temps : ~1h30 📅 Délai client : 2-3 semaines 📄 Version : mai 2026
📥 Brief client → 📁 Préparer assets → 🤖 Demander à Claude → 👁️ Valider → 🚀 Déployer → 📧 Livraison
Le process en 8 étapes
  1. Recevoir & valider le brief
  2. Préparer le dossier d'assets
  3. Demander la création à Claude

  5. Valider le résultat localement
  6. Itérer s'il y a des ajustements

1
👤 Toi

Recevoir & valider le brief du client

Tout commence par les réponses du formulaire Tally (ou un brief équivalent par email). Avant d'aller voir Claude, vérifier que tout est complet — sinon Claude va générer des placeholders et tu devras itérer.

Sources possibles

  • Idéal : le client a rempli le formulaire Tally (voir marketing/onboarding-form.md)
  • Acceptable : brief par email ou téléphone, retranscrit dans un fichier texte
  • À éviter : briefs oraux sans trace écrite — risque d'oubli

Checklist : qu'est-ce qu'il te faut absolument ?

  • Nom commercial + SIRET (optionnel pour l'affichage)
  • Slogan / tagline courte
  • Téléphone + email + zone d'intervention
  • 3 à 4 prestations principales (titre + description 1 phrase)
  • 1 prestation phare avec 4 points forts + 6 sous-prestations détaillées
  • Logo (PNG/SVG, fond transparent idéal)
  • 6 à 12 photos de réalisations
  • 3 témoignages clients (optionnel mais recommandé)
  • Couleurs souhaitées (codes hex ou descriptions)
  • Formule choisie (Essentiel 300 €, Pro 590 €, Pack annuel 890 €)
  • Validation des CGV signées
⚠️ Si une info manque

Ne lance pas Claude. Relance le client avec une liste courte et précise (max 5 points). Une relance vague (« il manque des trucs ») n'aboutit jamais. Préfère : « Pour démarrer ton site, il me manque : ton logo en PNG, 6 photos de chantiers, et 2 témoignages. Merci ! »

2
👤 Toi

Préparer le dossier d'assets du client

Pour que Claude puisse placer les bons fichiers aux bons endroits, mets logo et photos dans un emplacement précis sur ton PC.

Méthode recommandée : pré-déposer dans le bon dossier

  1. Choisir un slug court pour ce client (ex. garage-martin) — minuscules, tirets, pas d'accents
  2. Créer le dossier C:\Users\projets\templates-vitrine\clients\<slug>\assets\
  3. Y placer :
    • logo\ → le logo (PNG/SVG, fond transparent de préférence)
    • images\ → toutes les photos (bannières, galerie, etc.)

Comme ça quand tu briefes Claude tu peux juste dire « photos déjà déposées » au lieu de tout joindre dans le chat.

Alternative : joindre les fichiers dans le chat

Si tu préfères, tu peux glisser-déposer les fichiers directement dans la conversation avec Claude. Plus simple si tu as peu d'images. Plus lourd si tu en as 15.

💡 Optimiser les photos AVANT de les déposer

Photos d'iPhone brutes = 4-6 Mo chacune. Trop lourd. Passe par squoosh.app (gratuit, dans le navigateur) pour redimensionner à 1200-2000 px de large et compresser à < 200 Ko. Gain de poids : jusqu'à 95 %.

3
🤖 Toi → Claude

Demander la création à Claude

C'est l'étape clé : tu envoies à Claude un prompt structuré avec toutes les infos du brief. Claude va créer le config.json, placer les assets, lancer le build, et te dire où ouvrir le résultat.

Le prompt à utiliser

Le template complet est dans marketing/prompt-nouveau-client.md. Tu l'ouvres, tu copies, tu remplaces les [...] par les vraies infos du brief, et tu colles dans un nouvel onglet Claude Code.

C
Squelette du prompt
Crée un nouveau site vitrine pour un client à partir du template situé dans
C:\Users\projets\templates-vitrine.

TÂCHE
1. Crée le dossier `clients/<SLUG>/` avec sous-dossiers `assets/logo/` et `assets/images/`.
2. Crée le `config.json` complet pour ce client.
3. Place les fichiers d'assets aux bons endroits.
4. Lance `node build.js <SLUG>` et vérifie qu'aucun placeholder {{...}} ne reste.
5. Donne-moi le chemin du `index.html` à ouvrir.

INFOS CLIENT
- Slug : ...
- Nom commercial : ...
- Téléphone : ...
- Email : ...
- (etc. — voir prompt-nouveau-client.md pour la liste complète)

PHOTOS : déjà déposées dans clients/<slug>/assets/images/
LOGO  : déjà déposé dans clients/<slug>/assets/logo/
💡 Toujours nouvelle conversation

Démarre une nouvelle conversation Claude Code pour chaque client. Sinon le contexte des clients précédents pollue le travail. Une conversation = un client = un livrable propre.

Cas particulier : tu as un export Tally en CSV/JSON

Utilise la version courte du prompt :

Nouveau site client à générer dans C:\Users\projets\templates-vitrine.
Slug : <slug>
Réponses Tally ci-dessous :
[COLLER L'EXPORT CSV/JSON BRUT]
Assets déjà déposés dans clients/<slug>/assets/.
Mappe les réponses selon marketing/onboarding-form.md, crée clients/<slug>/,
lance le build, signale les infos manquantes.

Claude se charge de faire le mapping Tally → config.json en suivant le tableau de correspondance.

4
🤖 Claude bosse

Pendant que Claude bosse, tu attends (ou tu prends un café)

Claude va exécuter une dizaine d'actions automatiquement. Ne t'inquiète pas, c'est normal que ça dure 2 à 5 minutes selon la quantité de contenu.

Ce que Claude fait pendant ce temps

  1. Lit les références (templates-vitrine/clients/hipolem/config.json) pour la structure
  2. Crée le dossier clients/<slug>/
  3. Génère le config.json complet (toutes les sections, en respectant ta palette et tes textes)
  4. Vérifie que les assets sont bien là (logo + photos)
  5. Lance node build.js <slug> pour générer le site
  6. Vérifie qu'il ne reste pas de {{placeholder}} non résolu dans la sortie
  7. Te donne le chemin du index.html généré

À la fin, Claude te dira quelque chose comme ça

✓ Site généré : dist\garage-martin
  Ouvrir : C:\Users\projets\templates-vitrine\dist\garage-martin\index.html

Récap :
- Toutes les sections sont remplies
- 12 photos dans la galerie
- 3 témoignages
- Couleurs : #c0392b (primaire), #2c3e50 (secondaire), #f39c12 (tertiaire)

À noter : il manque le SIRET (champ non fourni dans le brief).
Veux-tu que je l'ajoute ou je laisse "non communiqué" ?
✓ Bon réflexe

Si Claude te signale des infos manquantes, note-les. Soit tu les laisses en placeholder, soit tu relances le client. Ne laisse JAMAIS un email ou téléphone placeholder en prod.

5
👤 Toi

Valider le résultat localement

Avant de mettre en ligne, ouvrir le site généré dans ton navigateur et faire une revue complète. Compter 15-20 minutes.

Ouvrir le site

Double-clic sur le fichier que Claude t'a donné : C:\Users\projets\templates-vitrine\dist\<slug>\index.html. Il s'ouvre dans ton navigateur par défaut.

Checklist de validation visuelle

  • Le logo s'affiche correctement (pas pixelisé, bien dimensionné)
  • Les couleurs correspondent à la palette demandée (CTAs, titres, accents)
  • Le titre H1 du hero affiche les couleurs si HTML utilisé
  • La bannière hero n'est pas déformée
  • Les 3 ou 4 prestations principales ont icône + titre + description
  • La section Showcase a ses bullets et sa mini-galerie
  • Les 6 mini-cartes (sous-prestations) sont remplies
  • La méthode 4 étapes est cohérente
  • La galerie : pas de cassure, toutes les images chargent
  • Lightbox fonctionne au clic sur une photo (s'ouvre en plein écran, flèches OK, ESC ferme)
  • Filtres de galerie fonctionnent
  • 3 témoignages affichés
  • Formulaire de contact : tous les types de projet adaptés au métier
  • Footer : nom, slogan, services, contact, mentions OK

Test mobile (important !)

Ouvre Chrome DevTools (F12 ou Ctrl+Shift+I) puis clique sur l'icône mobile (Ctrl+Shift+M). Choisis un format iPhone ou Galaxy. Refais le tour.

  • Le menu burger s'ouvre/ferme correctement
  • Le bouton appel flottant en bas à droite est visible
  • Pas de scroll horizontal (le site déborde pas)
  • Les boutons sont assez gros pour le pouce
  • Les photos restent lisibles

Test du formulaire de devis

Le formulaire n'enverra rien tant que tu n'as pas configuré Formspree. Pas grave à cette étape — tu le feras juste avant la mise en ligne. Pour l'instant vérifier juste que tous les champs (nom, tel, email, type de projet, message) sont présents.

6
🤖 Toi → Claude

Itérer s'il y a des ajustements

Si quelque chose ne va pas (couleur, texte, ordre des sections), tu retournes voir Claude et tu lui dis simplement ce qui doit changer. Pas besoin de toucher au code.

Exemples de demandes naturelles

Tu peux écrire à Claude des choses du genre :

C
Exemples de retours
  • « Le rouge est trop vif, passe-le à un rouge brique plus terreux »
  • « Intervertis les prestations 2 et 3 »
  • « Ajoute un témoignage : "Excellent travail !" — Marie L. »
  • « Le slogan ne me plaît pas, propose-moi 3 alternatives »
  • « Enlève la section Showcase, je veux pas mettre en avant une presta en particulier »
  • « Sur la galerie, les photos de salle de bain doivent être avant celles de la cuisine »
  • « La photo bathroom-3 doit être remplacée par celle que je viens de joindre »

Claude va modifier le config.json, rebuilder, et te dire ce qui a changé. Cycle court : tu demandes, tu refresh ton navigateur, tu valides.

💡 Un seul cycle de révision inclus dans le forfait

Côté client : 1 cycle de révision est inclus dans le tarif (Essentiel et Pro). Au-delà, c'est facturé 50 €/h. Pour TOI en revanche, tu peux itérer autant que tu veux avec Claude avant de présenter au client — c'est gratuit (sauf le coût de tes tokens Anthropic).

7
⚙️ Toi (action rapide)

Mettre en ligne sur le serveur

Une fois le site validé localement, deux options pour la mise en ligne selon que le client veut un sous-domaine ou un domaine perso.

Configurer le formulaire Formspree (avant tout)

  1. Aller sur formspree.io et créer un compte (ou se connecter)
  2. Créer un nouveau formulaire avec l'email du client comme destinataire
  3. Copier l'ID du formulaire (ex. xyzabc123)
  4. Dans l'admin web (gestia.ovh/admin) → édit du client → section ✉️ Formulaire de contact
  5. Remplacer VOTRE_ID_FORMSPREE par l'ID copié
  6. Cliquer « Sauvegarder & publier »

Scénario A — URL sous gestia.ovh (par défaut, rapide)

Le site est automatiquement accessible à https://gestia.ovh/<slug>/ dès qu'on le pousse sur le serveur.

Sur ton PC :

cd C:\Users\projets\templates-vitrine
git add . && git commit -m "Nouveau client <slug>" && git push

Sur le VPS gestia.ovh (vps-c4f983e3) :

gestia-update

C'est tout. Le site est en ligne à https://gestia.ovh/<slug>/.

Scénario B — Domaine custom du client

  1. Acheter le domaine (OVH, Gandi…) ou récupérer les accès au registrar du client
  2. Pointer le DNS vers le VPS gestia.ovh (135.125.159.92) : 
    Type: A    Nom: @     Valeur: 135.125.159.92
Type: A    Nom: www   Valeur: 135.125.159.92
    Attendre 5-30 min la propagation.
  3. Créer le vhost nginx sur le VPS : 
    sudo tee /etc/nginx/sites-available/<slug> > /dev/null <<EOF
server {
    listen 80;
    server_name <domaine.fr> www.<domaine.fr>;
    root /opt/site-builder/dist/<slug>;
    index index.html;
    location / { try_files \$uri \$uri/ /index.html; }
}
EOF

sudo ln -sf /etc/nginx/sites-available/<slug> /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
  4. HTTPS Let's Encrypt : 
    sudo certbot --nginx -d <domaine.fr> -d www.<domaine.fr>
💡 Astuce : demande à Claude

Tu n'as pas envie de te taper les commandes manuellement ? Demande simplement à Claude : « Mets en ligne le site garage-martin sur le domaine garage-martin.fr » et il te génèrera la séquence exacte à coller. Ou même mieux, dans une phase 2 de l'admin on automatisera ça par bouton.

📌 Bonus

Modifications mensuelles : l'admin web

Une fois le site livré, le client a droit à 1 modification mineure / mois (2 pour la Pro) incluse dans la maintenance. C'est là que l'admin web devient utile : tu y fais la modif en 2 minutes, pas besoin de Claude.

Workflow type pour une modif simple

  1. Le client t'envoie sa demande par email (ex. « change mon numéro, le nouveau c'est 06 22 33 44 55 »)
  2. Tu vas sur gestia.ovh/admin, tu te connectes
  3. Tu cliques sur la carte du client
  4. Tu modifies le champ téléphone (n'oublie pas le format international pour le lien : +33622334455)
  5. Tu cliques sur « Sauvegarder & publier »
  6. Tu vérifies sur l'URL du site que le changement est visible
  7. Tu réponds au client : « C'est fait, vérifiez sur <url> »

Total : 2 à 5 minutes. Pas de git, pas de Claude, pas de SSH. Juste un clic.
